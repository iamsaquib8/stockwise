# Termux (Android)

Two ways to get StockWise on an Android phone with
[Termux](https://termux.dev):

- **Prebuilt:** releases from 0.6.0 on have `stockwise-aarch64-linux-android.tar.gz`,
  built with the Android NDK (API 24, the Termux minimum). `install.sh` picks
  it on Termux and installs to `$PREFIX/bin`:

  ```bash
  pkg install curl
  curl -fsSL https://raw.githubusercontent.com/iamsaquib8/stockwise/master/install.sh | sh
  ```

  `cargo binstall stockwise` finds the same archive. Before that release,
  build it on the phone: `pkg install rust && cargo install stockwise`.
- **Termux repository:** `pkg install stockwise` once `build.sh` here is accepted into
  [termux/termux-packages](https://github.com/termux/termux-packages).

`build.sh` builds the `v0.5.0` source tarball with the Termux toolchain and
installs the binary, the man pages and bash/zsh/fish completions (generated by
a host build of the same source). It overrides the default make/install
steps because the source tree has a `pyproject.toml` (for PyPI), which the
default install step would treat as a Python package.

## Submitting (one time)

1. Fork `termux/termux-packages` and copy `build.sh` to
   `packages/stockwise/build.sh`. If a newer tag is out, set
   `TERMUX_PKG_VERSION` to it and `TERMUX_PKG_SHA256` to
   `curl -sL https://github.com/iamsaquib8/stockwise/archive/refs/tags/v<version>.tar.gz | sha256sum`.
2. Build it with the official builder (Docker on an x86_64 Linux machine; on
   Apple silicon use the `termux` job's artifact from packaging.yml instead):

   ```bash
   ./scripts/run-docker.sh ./build-package.sh -a aarch64 stockwise
   ./scripts/run-docker.sh ./build-package.sh -a x86_64 stockwise
   ```

   Install the `.deb` from `output/` on a phone (`apt install ./stockwise_*.deb`)
   and run `stockwise doctor`.
3. Commit as `addpkg(main/stockwise): 0.5.0` and open a pull request. Termux
   asks that new packages are reasonably popular and actively maintained; link
   the release page and the Android build in the description.

`TERMUX_PKG_AUTO_UPDATE=true` lets Termux's bot bump the version and checksum
on new tags.

## Checks

`.github/workflows/packaging.yml` builds `aarch64-linux-android` with the
runner's NDK and syntax-checks `build.sh` on packaging changes. A release
build with NDK r28 (`cargo build --release --target aarch64-linux-android`,
API 24 clang) was run on an Android 16 arm64 emulator through `adb shell`:
`--version`, `doctor`, a live `quote` over HTTPS and a watchlist write work;
the OS keyring is reported as unavailable and secrets stay in owner-only
files, as on other systems without one. Not yet run inside the Termux app
itself. The `termux` job in packaging.yml builds `build.sh` with the official
builder on GitHub's x86_64 runners; locally on Apple silicon the builder image
fails to unpack sources under emulation (`tar: Cannot mkdir: Function not
implemented`), so that job is the place to check the recipe.
